# What writing *Raku Behind the Docs* found

*Living document, started 2026-09-28. Oracle: Rakudo v2026.08.*

*Raku Behind the Docs* is an interactive book of Raku behaviours, published
at raku.online/deep/, with its source in the raku-behind-the-docs repository
(github.com/ash/raku-behind-the-docs). It rewrites the semantics sheets in
[`semantics/`](semantics/) for readers: every sheet item became one or more
*corners*, each a claim with a short program and the output Rakudo prints.
The book's build runs every program on Rakudo and fails on any difference,
and runs the same programs on Raku++.

Rewriting a sheet's one-line megaprobes as short programs meant re-running
every probe, on its own, on Rakudo. That produced three kinds of result,
recorded here:

1. **Sheet corrections.** Places where a sheet's prose disagrees with Rakudo,
   and often with the sheet's own recorded output. The sheets are the input
   to step two of the semantics campaign, so an implementer working from one
   of these items would build the wrong behaviour.
2. **Behaviours beyond the sheets.** Rakudo behaviour the sheets do not
   record, found while writing the corners. Most are in the book; a few were
   probed once and left out, and are marked so.
3. **Raku++ divergences.** Every book example on which Raku++ prints
   something other than Rakudo, generated by the book's build into
   [`behind-the-docs/raku-divergences.md`](behind-the-docs/raku-divergences.md).

Chapters written so far: 0–18 (913 corners, 1,250 examples). The chapters
from IO, Proc-Async, Promise and Supply are being written; their findings are
added when they land.

## 1. Sheet corrections

Each entry names the sheet item, the book chapter that re-probed it, and what
Rakudo v2026.08 actually does. "The sheet's own output" means the Rakudo
output recorded in the sheet already shows the correct behaviour and only
the prose misreads it.

### Compiler-Side.md

- **CP-15** (ch 5): a sunk call ending in `1` or `0` KEEPS a `let` change;
  the sheet's own output shows 2. `let` restores only when the block is left
  by an exception or ends with an undefined value (`Nil`, `Any`, a Failure);
  every defined value keeps the change, used or sunk. The "let quirk" does
  not exist.
- **CP-17** (ch 7): `1e10 =~= 1e10 + 1` is False.
- **CP-18** (ch 9): `1 xx NaN` and `1 xx "b"` throw when the Seq is built,
  not when it is read.
- **CP-19** (ch 2): `\x[110000]` in a source file is a compile-time error;
  only under `EVAL` is it `X::AdHoc`.
- **CP-23** (ch 2): `q:!q` says "Too late for :q"; only `Q:!q` says "Cannot
  negate".
- **CP-24** (ch 2): `q|a|b|` is "Two terms in a row", not an unterminated
  string.
- **CP-25** (ch 2): a heredoc line indented less than the terminator loses
  ALL its leading whitespace and the compiler warns "Asked to remove N
  spaces"; it is not left as is. `\r\n` inside an EVAL'd heredoc stays
  `\r\n` (the sheet's own output); only a real CRLF source file gets `\n`.
- **CP-27 / CP-31** (ch 4): the rule for the last statement of a `for` body
  was measured only inside `try`. A plain `for` block sinks it (`for 1 { run
  "false" }` throws at top level); under `use fatal`, which every `try` turns
  on, it is not sunk, whatever the value; with a pointy block
  (`-> $x { … }`) a method call at the end is sunk but a sub call is not, so
  `for @cmds -> $c { run $c }` ignores failures.
- **CP-30** (ch 4): after `.defined` has handled a Failure, `.Int` does not
  throw (the sheet's own output): it gives the `Int` type object, `+$x` gives
  NaN and `.Str` gives "(HANDLED) message" with the backtrace. Only `.chars`,
  `.elems`, `.list` and the like still throw.
- **CP-32** (ch 4): a Seq returned by an explicit `return` and then sunk IS
  iterated (the sheet's own output says 3); `.head(1)` runs one element, not
  to the end.

### Code-Introspection.md

- **CO-02** (ch 15): for `sub f(--> 42)`, `&f.returns` is `Int`; only
  `.signature.returns` is 42 (the sheet's own output).
- **CO-17** (ch 15): the deprecation report counts routines, not calls ("Saw
  1 occurrence" after two calls).
- **CO-18** (ch 15): two modules in one file that export the same name fail
  at compile time ("already been exported"), not at import.
- **CO-20** (ch 15): `is tighter(&infix:<+>)` on a sub that is not an
  operator compiles without complaint; only the string form `is tighter<+>`
  is refused.
- **CO-28** (ch 15): `.named_names` lists the innermost name first (`(b a)`),
  not the outermost (the sheet's own output).
- **CO-29** (ch 15): a plain `$x` bound to a literal still shows `.VAR` as
  `Scalar`, and `+a` given an Array produces a List, not an Array (both the
  sheet's own output). Slurpy elements are Scalars only when at least one
  argument is a variable: with all literals, `*@a` holds bare values and
  assigning to an element dies; `+@a` and `**@a` do not do this.

### Nil-Any.md

- **NA-06** (ch 6): `ASSIGN-POS`/`ASSIGN-KEY` on a type object throw
  `X::Assignment::RO`, not `X::AdHoc` (the sheet's own output). `BIND-KEY`'s
  Failure holds `X::Parameter::RW`, whose message names `'(Any)'`; only
  `BIND-POS` gives `X::Bind`.
- **NA-07** (ch 6): the list of string methods that answer an empty string on
  Nil is incomplete: `trim`, `samecase`, `NFC` and `encode` die with
  `X::Multi::NoMatch`, and `split` goes through string context.
- **NA-13** (ch 6): `@e[5]` prints `([], Any)`, as the sheet itself notes.
- **NA-18** (ch 6): not every enum overrides `.kv`. A user enum value and
  `Less` give their own name and number; only `True`/`Bool` gives the whole
  table. The sheet's recorded Bool line depends on hash order.
- **NA-26** (ch 9): `squish :with` receives the previous element, not the
  previous kept one; `unique` passes the new element first and compares it
  only with the elements it kept.
- **NA-27** (ch 6, ch 9): `($(a=>1,b=>2), 3, 4).pairup` dies with
  `X::Pairup::OddNumber`; it does not pair 4 with Nil.

### Int-Num-Rat.md

- **N-05** (ch 7): a terminating fraction is still rounded in `.Str`:
  `(1/1024).Str` is `0.000977`.
- **N-07** (ch 7): `Int.Int` returns the type object, not 0. `max`/`min` skip
  an undefined number without warning (`$n max $n` is `-Inf`); `cmp` compares
  it as a string, with a string warning.
- **N-09** (ch 7): `"abc" != 3` is True.
- **N-10** (ch 7): `$*RAT-OVERFLOW = FatRat` has no effect on `1/(2**64)`
  written with literals, because the division is done at compile time. It
  works with a variable operand, or under `try`.
- **N-12** (ch 7): `0e0 ** -1` is Inf. The Underflow Failure in the sheet's
  output belongs to `Inf ** -1`, which is the real bug. `$x ** 2` with a
  literal 2 gives `0e0` where other exponents fail.
- **N-16** (ch 7): `[max] 1, 1.0` keeps the second value; only three or more
  operands keep the first.
- **N-17** (ch 7): not only -64: every negative `+<` count past -63 wraps
  modulo 64 on an Int that fits in 64 bits (`1024 +< -65` is 512).
- **N-20** (ch 7): the camel-case base form is not on docs.raku.org, although
  the sheet marks it documented.
- **N-25** (ch 7): `log(8, 2)` is exactly 3; `1000.log10` is the inexact one.
- **N-26** (ch 7): after `srand`, the first run of a piece of code draws
  different numbers from later runs of the same code, which replay, `pick`
  included; this is deterministic across program runs. The effect is per
  kind of draw (ch 11): the first `pick` after `srand` differs even from a
  different line.

### Str.md

- **ST-07** (ch 8): a signed denominator is accepted: `"1/-2"` numifies to
  -0.5.
- **ST-19** (ch 8): `_` does not split words for `.wordcase`:
  `"a_b c".wordcase` is `A_b C`.
- **ST-22** (ch 8): trailing whitespace is replaced when the pattern has a
  run in that position.
- **ST-33** (ch 8): ǅ does not match dž, nor İ match i̇, under `:i`, although
  `"İ".fc eq "i\x[307]".fc` is True.
- **ST-35** (ch 8): the `*-N` advice also appears for a start past the end
  (`use *-4`); a start below -chars gets none, and its message ends in a
  stray "; ".
- **ST-48** (ch 17): a single `:nth` with `:x` gives `()` (the sheet's own
  output), not the one match; tagged a bug, as GM-33.
- **ST-49** (ch 17): `:c(Nil)` anchors at 0, like `:p(0)`; see GM-34/35.
- **ST-50** (ch 8): `"abc".subst("", "-", :g)` is `a-b-c`, not `-a-b-c-` as
  with `/<?>/`. `:as(Str)` throws with `:g`, `:nth` or `:x` for either kind
  of needle; a regex with a single match works.

### List-Array.md

- **LA-24** (ch 9): `splice(0, 1)` on a lazy array works and returns `[1]`.
  `splice(1)` or `splice(1, *)` removes only the part computed so far,
  returns `[]` and raises no error (tagged a bug in the book).
- **LA-28** (ch 9): "assigning the Seq into an array caches it" is wrong: the
  probe's Seq sat in `$s`, so it went in as one element and was never
  iterated. Assigning a bare Seq consumes it.
- **LA-30** (ch 9): "a lazy side never matches" is contradicted by the
  sheet's own `(1,2).Seq ~~ (1..*)`, which is True: a Range on the right
  compares the list's length, so `(5,6) ~~ 1..2` is True too.
- **LA-33** (ch 9): `X` is lazy when ANY operand is lazy, not only the first.

### Hash-Map-Pair.md

- **HM-04** (ch 10): the key in `%h<1>` is an `IntStr`, not a Str. It passes
  an `Int` key check, and in `my %h{Any}` it is a third key, separate from
  `1` and `"1"`.
- **HM-15** (ch 10): `.fmt` follows the hash's own, random, order; the
  sheet's sorted output was luck. (The gist, `.Str` and `.raku` of a Hash or
  Map ARE sorted by key string; `.keys`, `.values`, `.fmt` and `.map` are
  not.)
- **HM-16** (ch 10): `Int => 1` and `Nil => 1` have the STRING keys "Int"
  and "Nil"; a real type-object key prints as `(Int) => 1`.

### Range.md

- **RG-02** (ch 11): `(1..*+1).^name` prints `WhateverCode.new` because
  parentheses do not end a Whatever expression and `.^name` becomes part of
  the code; assigned to a variable first, `.^name` is `WhateverCode`. Not a
  gist quirk.
- **RG-04** (ch 11): `(1 .. "5").is-int` is True (the sheet's own output),
  not False.
- **RG-21** (ch 11): `(1..2) ~~ ((1..2) but role {})` is True (the sheet's own
  output); a mixed-in role does not change the answer.
- **RG-24** (ch 11): `(1..2) cmp (1,2,3)` and `(1..2) cmp 2` are both Less
  (the sheet's own output).
- docs.raku.org says `'5' ~~ *..10` is False; Rakudo says True.

### Sequence.md

- **SQ-03** (ch 12): `1 ... (3, 9)` gives `(1, 2, 3, 9)`, like the scalar
  form; it is not one List endpoint that never matches.
- **SQ-05** (ch 12): a Range that is the whole right side is flattened
  (`1 ... 3..5` is 1 to 5: endpoint 3, then 4 and 5 appended); a Range is
  matched by containment only inside a longer list. A non-numeric endpoint
  always walks upwards, so `5 ... "3"` never ends. A `False` endpoint matches
  nothing, and the sequence never ends (and is not lazy).
- **SQ-10** (ch 12): seeds before the last three are emitted before the
  deduction error; they are not lost.
- **SQ-21** (ch 12): not a quirk. The probe's `for $s` pushed the Seq itself,
  and `@got.raku` then read it outside the `try`; with `try { for @$s … }`
  the error is caught.
- **SQ-28** (ch 12): chained `...^` fails with `X::TypeCheck::Argument` ("will
  never work with signature of the proto");
  `X::Syntax::NonListAssociative` is what mixing `...` with `...^` gives.

### Set-Bag-Mix.md

- **SB-07** (ch 13): "total changes from 0.5 to 1.4" mixes two probes. A
  total computed before `.Bag` stays stale, and so does the WHICH: after the
  truncation the Mix is still `===` to the original.
- **SB-15** (ch 13): which weight survives a `.Map` collision varies from
  run to run; there is no fixed "later one wins".
- **SB-24** (ch 13): the SetHash/BagHash hyper "returns the ORIGINAL
  contents" only because postfix `--` returns old values; prefix `--`
  returns the new ones. The Mix truncation happens for hyper postfix, prefix
  and method calls, but not for infix hyper (`$m >>+>> 1` keeps 2.5).
- **SB-26** (ch 13): `mix(<a>).grabpairs` throws `X::Immutable` (the sheet's
  own output); only MixHash allows it.
- **SB-40** (ch 13): a whole-file `use v6.c` does bring `(<+)` back, with a
  deprecation report; only the `EVAL` case fails.
- **SB-44** (ch 13): `my @a = $b`, with a Bag in `$b`, gives one element, the
  Bag (the sheet's own output, "1 Bag"). `for $b` runs once because of the
  `$` container; `for bag(...)` and `for $b<>` iterate the Pairs.

### Blob-Buf.md

- **BB-12** (ch 14): `splice(-1, 1)` does not leave a leading 0: it removes
  the last element (in general the element n places from the end) and still
  returns a Failure. `splice(o, -1)` at offset 0 adds a 0; at other offsets
  it duplicates the element before the offset.
- **BB-15** (ch 14): `Z` walks through a buffer value, but a buffer held in a
  `$` variable is itemized and taken whole; `X` takes it whole either way.
- **BB-25** (ch 14): `:strict` does not win over `:replacement` (the sheet's
  own output shows `(63,)`): `:strict` decides what counts as unencodable,
  `:replacement` what it becomes.
- **BB-29 / BB-32** (ch 14): on a 16/32/64-bit buffer the offset of
  `read-*`/`write-*` counts elements, not bytes; the width is in bytes, read
  from raw storage, and a write grows the buffer by one element per byte.
  "Bytes land one per element" is wrong:
  `buf16.new.write-uint16(0, 0x0102, LittleEndian)` is `(258, 0)`.
- **BB-33** (ch 14): the clobbering is regular: of the bits right of the
  written run, only the first survives
  (`buf8.new(0xFF).write-ubits(0, 4, 0)` is 8).

### Exception-Backtrace.md

- **EX-10** (ch 16): inside a CATCH, `$!` is Nil, not the enclosing `$!`
  (the sheet's own output). A handled exception never becomes `$!`, and a
  `try` whose CATCH handles it leaves `$!` untouched.
- **EX-13** (ch 16): the value is Nil in every case, never "Any otherwise"
  (the sheet's own output).
- **EX-17** (ch 16): CONTROL never sees the CX::Succeed or CX::Proceed of a
  `when` block ("succ" and "proc" are missing from the sheet's own output);
  it does see a `succeed` written outside a `when`.
- **EX-25** (ch 16): outside a `try`, assigning a Failure to `my Int` throws
  `X::TypeCheck::Assignment`, reported as "Earlier failure: … Final error:
  …"; only inside a `try` is it the Failure's own exception.
- **EX-31** (ch 16): `$!` in a LEAVE is the exception only when the LEAVE is
  in the `try`'s own block. In a dying sub it is the sub's own `$!` (Nil);
  beside a CATCH that handles the exception it is whatever `$!` held before.

### Grammar-Match.md

- **GM-22** (ch 17): `(a)|(b)(c)` does not always have two slots: `.elems` is
  1 when the first branch wins; the count follows the winning branch.
- **GM-34 / GM-35** (ch 17): `:c(Nil)` does not mean 0 in the sense the sheet
  gives: it anchors at 0, like `:p(0)`; `:p(Nil)` searches as if absent (the
  sheets' own outputs).
- **GM-41** (ch 17): the `"abc".trans([1,2] => "x")` probe could never fail,
  since "abc" has no digits; `"a1b2".trans([1,2] => "x")` gives `axbx`. Only
  a Regex type-object key is really skipped.

### Date-Time.md

- **DT-13** (ch 18): `.sum` of a Date range is a Date only when the count is
  odd; an even count gives an Int. It follows from DT-11's fallback (Date +
  Date is an Int, Int + Date a Date), and a plain list of Dates does the
  same. A quirk rather than a bug.
- **DT-15** (ch 18): truncation units are not matched by "first characters":
  the word must BEGIN WITH the whole unit name. "weekend", "yearning" and
  "hourglass" work; "mon", "y" and "daily" are refused.
- **DT-17** (ch 18): `:year` beside `:date` does not throw `X::AdHoc` (the
  sheet's own output shows `2000-01-01T00:00:00Z`): the date is thrown away.
  `:month` or `:day` beside `:date` replace just that part.
- **DT-23** (ch 18): a Num second below 5e-7 prints six decimals, not seven
  (the sheet's own output, and probes from 1e-7 down to 1e-20).

## 2. Behaviours beyond the sheets

Found while writing the corners, grouped by chapter. Entries marked *(not in
the book)* were probed and left out of the chapter; the rest are corners,
verified by the book's build on every run.

- **Quotes (ch 2).** `"\c[BELL]"` is U+1F514; the control character is
  `\c[BEL]`. `<< a$b >>` gives two words while `qqw{a$b}` gives `"ab"`.
  `qww{"$x"}` interpolates. `"$n{1}"` and `"$name()"` are a subscript and a
  call. `1 ∈ <1 2 3>` is False (allomorph keys). The undefined-value warning
  says "value element" and does not name the variable. *(Not in the book:*
  `q:regex{a}` leaks "Cannot look up attributes in a Perl6::RegexGrammar type
  object".*)*
- **Whitespace (ch 3).** `:1_000days` is the pair `:_000days(1)`;
  `:2.7days` fails as a malformed radix number. A line starting `=word`
  followed by a space is an abbreviated Pod block and silently swallows code
  up to the next blank line, even mid-statement. `if(`, `for(`, `while(`,
  `loop(`, `given(`, `when(` and `with(` are refused, but `elsif(` and
  `orwith(` are accepted. Inside `[ ]` or `( )`, a `}` at the end of a line
  acts as `;`, so a list of hashes one per line needs no commas. `a`, a
  newline, then `=>` does not quote `a`. `sub X` and `sub Int` cannot be
  called as `X(…)`/`Int(…)` (coercions). `< >` does not split at U+00A0,
  U+2007 or U+202F, while `.words` does. `#|` attaches to the next
  declaration across intervening statements. *(Not in the book:*
  `my $x-1 = 2` redeclares `$x`, keeps its old value, then dies "Cannot
  modify an immutable Int".*)*
- **Sink (ch 4).** `try { run "false" }` does not catch the failure: the Proc
  is sunk after the `try` has finished. Inside `try`, `.defined`, `with` and
  `orelse` throw a returned Failure; only `//`, `||`, `?? !!`, `if` and `so`
  test it first. Several "Useless use" warnings of one program come out in a
  random order. A `given` with no matching `when` gives `False`, or `0` when
  the topic is undefined. A sunk `map` does not sink the values it produces.
- **Containers (ch 5).** `@a = @a, 3` and `@a ,= 3` store the array inside
  itself. `@a[0] += 10, 20` is an item assignment, unlike `@a[0] = 10, 20`. A
  `$` name bound to a list is not itemized, so `for` iterates it. List
  assignment to a bound List assigns into each element in turn
  (`my @l := ($a, $b); @l = 3, 4` sets `$a` and `$b`). *(Not in the book:*
  `@a».<>` dies ".nodemap only supports Callables with a single parameter,
  got 3"; `my ($p, $q?) := (1,)` leaves `$q` as `Mu`.*)*
- **Nil and Any (ch 6).** `Nil[0]` is a compile error, "Any cannot be
  parameterized", and `Nil{…}` is "Autovivifying object closures not yet
  implemented". `42[Int]` prints a stray "Use of Nil in string context".
  `my Num $n; $n++` gives `1e0`, while Rat and Str variables refuse the
  increment. `Int.min` dies, but `min(Int)` is `Inf`. `().pick(2)` returns a
  List where `().roll(2)` returns a Seq. *(Not in the book:* an optional
  pointy parameter `$b?` gets `Mu`, not Any.*)*
- **Numbers (ch 7).** `7 mod 0` reports "using div". `42.expmod(-1, 7)` dies
  with the big-integer library's own message, "Error in mp_exptmod".
  `0.polymod(10 xx *)` is an empty Seq. `(1/3).base(10, *)` does not return.
- **Strings (ch 8).** *(Not in the book:* `"½".Numeric` returns a RatStr;
  `encode` also hangs with an unset `Any` variable; `"ab" x Inf` says "Cat
  object not yet implemented"; `rindex(<a b>, 1)` spins at 100% CPU.*)*
- **Lists (ch 9).** A Slip stored in `$s` or wrapped in `$( )` still flattens
  into the surrounding list, and `for $s` iterates it. `is-lazy` is False
  even for an endless `gather`, so `my @a = gather { loop {…} }` hangs. The
  splice error message's size range is one short (`0..^2` where 2 is
  accepted). `.join` consumes a Seq, while `.Str` and indexing keep its
  values.
- **Hashes (ch 10).** In `my %h = @pairs, c => 3`, an Array, List, Seq or
  itemized hash inside the list becomes one stringified key; only a bare
  Hash or Map is spread. `%h{'a';'b'}` returns a one-element List (`+1`
  gives 2, `++` dies) while `@a[0;1]` returns the element. An adverb attaches
  to the loosest operator before it that binds tighter than item assignment:
  `1 + %h<a>:exists` is `X::Multi::NoMatch`, and next to `&&`, `==` or `??`
  it is refused at compile time. `push` onto a value that is an existing
  Array modifies that array. `(a => 1).Capture` is
  `\(:key("a"), :value(1))`. `Map.new` and `Hash.new` silently drop named
  arguments when positional ones are also given. *(Not in the book:* `:{}` is
  `Hash[Mu,Mu,Any]` while `my Mu %h{Mu}` is `Hash[Mu,Mu]`.*)*
- **Ranges (ch 11).** `(1e0..3e0).sum` is the Int 6 while `.list.sum` is
  `6e0`. `Inf..Inf` yields nothing and `.elems` fails on it, yet
  `+(Inf..Inf)` is Inf. Under `use v6.e.PREVIEW` an empty range is False.
  `Seq.List` reifies lazily, which delays draws made after `srand`. A lazy
  list's `.pick` returns a Failure, an endless Range's `.pick` returns Nil.
- **Sequences (ch 12).** Tagged as Rakudo bugs in the book, none in the sheet:
  `-1, -2, -4 ... -16` is empty and `-1, -2, -4 ... -0.5` never ends; a
  generator returning a Slip has its endpoint tested once per call against the
  whole Slip (`1, { slip 5, 6 } ... 2` stops); a chain always emits its last
  endpoint (`1 ... 5 ... 7.5` ends `7, 7.5`), which is also why a chained
  `^...^` keeps its end; `...^` does not drop the end for equal-length
  strings of two or more characters. *(Not in the book:* `'a' ... 'c'|'e'`
  dies "expected Callable but got Junction"; `1+2i ... 5` hangs.*)*
- **Sets (ch 13).** A chained `A ⊖ B ⊖ C` is already the n-ary form. The
  lazy-operand `X::Multi::Ambiguous` also happens with an infinite Range.
  `$h (|)= <b>` puts a new SetHash in the variable, so another reference to
  the old one does not see the change.
- **Buffers (ch 14).** A replacement the encoding cannot hold dies
  (`:replacement("é")` under ascii). Non-strict windows-1252 writes U+0080 as
  byte 0x80, which decodes as €. `decode(Str)` means UTF-8, while
  `encode(Str)` hangs. `.decode(:translate-nl)` does nothing, but a decoder
  built with it translates. `pack("C*", 1, 2)` packs only the first value.
- **Signatures (ch 15).** `$v ~~ * > 3` becomes a chained WhateverCode,
  `$v ~~ $arg && $arg > 3`. *(Not in the book:* naming a sub `int` or `str`
  collides with the native-type coercion syntax; `.map(*.VAR.^name)` dies
  "Did a * (Whatever) get absorbed"; `import` happens at compile time, so an
  `import` later in the file affects an earlier `EVAL`.*)*
- **Exceptions (ch 16).** An uncaught stray `last`, `next` or `redo` prints a
  `===SORRY!===` header with no backtrace, although it is a run-time error.
  The `.gist` of a `:without-backtrace` exception lists the frames where
  `.gist` is called. A printed `warn` shows only the innermost frame. A
  Failure thrown away from where it was made adds an "Actually thrown at:"
  section. The DESTROY warning for an unhandled Failure is nondeterministic
  (19,409 versus 16,633 warnings on two identical runs). *(Not in the book:*
  in `.list` and `.full` the `<unit>` frame's `.line` is one past the
  statement; `.is-compile-time` answers 1, not True, for X::Undeclared.*)*
- **Regexes (ch 17).** `<.name>` never looks up a lexical regex: with
  `my regex foo`, `<.foo>` dies "No such method 'foo'". A lexical
  `my regex ident` hides `<ident>` even inside a grammar declared in its
  scope. `{}` ends the part of a branch that `|` measures; `<?{ }>` and
  `:my` do not. `my Str $s; $s ~~ /^$/` matches: the type object is treated
  as the empty string. `"abc" ~~ S/x/y/` is True, because nothing was
  replaced. `:as(Str)` is ignored with `:c` or `:p`. `Grammar.parse` dies with
  a P6opaque `%!hash` message, and a grammar without TOP suggests "Did you
  mean 'to'?". *(Not in the book:* a space between letters in a regex raises
  the "Space is not significant" worry only once per file.*)*
- **Dates (ch 18).** `my $*TZ` reaches `.local` but not `DateTime.now`, which
  follows only an assignment to the process-wide `$*TZ`.
  `DateTime.new("…Z", :timezone(3600))` keeps the clock and changes the
  label, so the result is a different moment from the one the string names.
  A Date made from a DateTime inherits a formatter that can crash `.Str`.
  `DateTime - Date` subtracts the Date's day count as if it were seconds. A
  non-numeric month, or a fractional count on a Date, dies with Rakudo's
  internal "cannot unbox" message as an `X::AdHoc`.

## 3. Raku++ divergences

[`behind-the-docs/raku-divergences.md`](behind-the-docs/raku-divergences.md)
lists every book example on which Raku++ disagrees with Rakudo: the code,
Rakudo's verified output and Raku++'s output, grouped by chapter and corner,
with a per-chapter count at the top. It is generated by the book's build and
names the Raku++ version it measured; regenerate it rather than editing it:

    rakupp build.raku --verify --report=<raku++>/docs/dev/findings/behind-the-docs/raku-divergences.md

run in the book's checkout. A divergence is a different standard output, or
one engine rejecting a program the other runs. Examples that touch files,
processes or threads (marked *local*) are included; the book pages show them
without a Run button.

At its generation on 2026-09-28 (chapters 0–18, Raku++
4.0.1-240-g0aca2320), Raku++ matched Rakudo on 595 of 1,235 examples. The
chapters where it matches least are Blobs and Bufs (8 of 87), Dates and
Times (18 of 70), Sets, Bags and Mixes (22 of 82), The Sequence Operator
(20 of 45) and Ranges (22 of 51); it matches most in Who Takes the Operand
(38 of 41) and Hashes, Maps and Pairs (39 of 50).

One Raku++ bug found in passing deserves its own line: for the chapter 9
example `my @a = 1..*; say @a.splice(1, 2).raku; …`, Raku++ prints the
`.raku` of an ever-growing array without end, 284 MB in the 20 seconds
before the alarm stopped it. Rakudo prints `[2, 3]` and `(1, 4, 5).Seq`.
