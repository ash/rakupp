# Twenty distributions to fix the compiler against

2026-09-15, engine `3.28.0-64-g9ad1caa`.

Every dist below was **re-measured on that build** before it was written down —
`tools/eco-fresh/sweep-fresh.raku`, 90 s budget, one shard, against a seeded
store. Thirty-six candidates were checked and **all thirty-six still fail**:
29 on their own suite, 7 behind a dependency. The run is
`probe-next20-2026-09-15.tsv`; the board it was drawn from is
`board-2026-09-14.tsv` (972 of 2,529 passing).

Candidates were ranked by how many not-yet-green dists sit transitively
downstream (`tools/eco-fresh/dep-leverage.raku`, the `lev` column) and by how
many dists share the same first error (`clu`), then filtered to failures that
are the engine's fault: native-library and windowing-system failures are not in
this list.

## Part 1 — eight dists, nine gaps that reproduce in one line

Each program was run under this build and under Rakudo 2026.08 at
`/opt/homebrew/bin/raku`. Every one of them runs on Rakudo.

| # | dist | lev | the program | rakupp | Rakudo |
|---|---|---|---|---|---|
| 1 | Testo | 31 | `rx/a/.cache` | `X::Method::NotFound` | `(rx/a/,)` |
| 2 | AttrX::Mooish | 23 | `class C { has $.x }; C.^get_attribute_for_usage('$!x')` | `X::Method::NotFound` | `Attribute` |
| 3 | Identity::Utils | 17 | `CompUnit::DependencySpecification.new(short-name => 'M')` | names itself `DependencySpec`; `~~ CompUnit::DependencySpecification` is **False** | the type it says it is |
| 4 | Cro::WebApp | 15 | `class C is implementation-detail { }` | does not compile — the trait is read as a **superclass** | compiles |
| 5 | Clipboard | 11 | `Proc.new` | `X::Method::NotFound` | `Proc` |
| 6 | CSS::Properties | 7 | `class C { submethod TWEAK(::?CLASS :$copy, :module($)) { } }` | `Cannot put required parameter $copy after named parameters` | compiles |
| 7 | Apache::LogFormat | 9 | `my $x = q~tilde quoted~;` | `Missing required term after infix` | runs |
| 8 | Data::Dump::Tree | 6 | `my $s = "abc"; $s ~~ s~b~X~;` | `unexpected operator in term position` | `aXc` |
| 9 | Data::Dump::Tree | 6 | `f(:title( S/(' ')$// given $str ))` | `expected ) (got 'given')` | runs |

Notes on four of them:

- **3** is two faults, not one. Beside the constructor naming,
  `Distribution::Path` does not exist here at all (`::('Distribution::Path')` is
  a Failure; Rakudo has the type), and the same suite then fails
  `The object is-a 'CompUnit'`. Six dists share this first error — MCP, PURL,
  SBOM::Raku, Pod::TreeWalker, CoreHackers::NfaChainsaw, Identity::Utils.
- **6** is narrower than it looks: `::?CLASS :$copy` alone parses, and
  `:module($)` alone parses. It is the pair that does not. CSS::Properties'
  `TWEAK` has both, and the error is reported two lines past the cause.
- **7** and **8** are one gap from two sides: **`~` is not accepted as a quote
  delimiter**, in `q~…~` and in `s~…~…~`.
- **9** is a statement modifier inside a parenthesized argument. Rakudo parses
  `given` there; this build stops at it. Data::Dump::Tree needs both 8 and 9,
  and has two more parse errors behind them (`Confused (got ')')` at
  `DHTML.rakumod:113` and `Diff.rakumod:67`).

Two smaller divergences turned up beside these, each worth a regression row
rather than a campaign: a `List()` coercion of a list gives `(1, 2)` here where
Rakudo itemizes to `$(1, 2)`; and `.cache` above is the only `.cache` this build
refuses.

## The one that is a decision, not a bug

**NativeHelpers::Blob** is the biggest single lever left outside the async
constellation — **47 not-green dists downstream** — and no engine fix reaches
it. Its `t/CompileTestLib.rakumod` reads:

```raku
if $VM.name eq 'moar' { … }
elsif $VM.name eq 'jvm' { … }
else { die "Unknown VM; don't know how to compile test libraries" }
```

and then builds a C test library out of `$*VM.config<cc obj ccshared ccout
cflags ld ldshared ldflags ldlibs ldout>`. Reaching it means answering `moar` —
which this project decided against — or shipping `$*VM.config` in the moar shape
*and* getting the dist patched upstream. Worth a decision before anyone costs
the 47.

## Reproducing

    rakupp tools/eco-fresh/sweep-fresh.raku --store=<store> --logs=<logs> \
        --out=<out.tsv> --timeout=90 <list.tsv>

The list is pick-fresh shaped (`date  name  version  dist`); the store here was
a copy of the default install store, so no dist is blocked by a dependency that
is merely absent. Named arguments must come **before** the positional.

Parse gaps were named by unpacking the fez or REA tarball printed by
`rakupp install --dry-run NAME` and running `rakupp -c -I lib` over every module
in it. That is also how PDF::Content and Cro::HTTP were found to have **no parse
errors left** — two board rows that had gone stale.

## What was fixed against this list (same day)

Thirteen engine faults, each with a regression file in `t/regression/` that
passes under Rakudo 2026.08 byte-for-byte:

| # | the fault | what it unblocked |
|---|---|---|
| 1 | `~` was not accepted as a quote delimiter (`q~…~`, `s~…~…~`, `m~…~`) | Apache::LogFormat and Data::Dump::Tree parse |
| 2 | a statement modifier inside a colonpair's value parens | Data::Dump::Tree's `:title(S/…// given …)` |
| 3 | a bare type in a list declaration was not an anonymous slot | Stats parses |
| 4 | `::?CLASS` typing a NAMED parameter became a required positional | CSS::Properties parses and constructs |
| 5 | `is implementation-detail` was read as a superclass | Cro::WebApp compiles |
| 6 | `Proc.new` did not exist; `.shell`/`.spawn` now run an unspawned Proc | **Clipboard is green** |
| 7 | `CompUnit::DependencySpecification.new` named itself `DependencySpec` | Identity::Utils' first assertions |
| 8 | Code objects (a sub, a block, a Regex) had no one-element list view | Testo gets past `.cache` |
| 9 | `.^get_attribute_for_usage` did not exist | AttrX::Mooish reaches its own Attribute subclass |
| 10 | a `*@slurpy` candidate tied with one that DECLARES the parameter | Text::CSV's `combine` stops recursing |
| 11 | `Slip.from-iterator` answered a List, and a Slip's `.raku` hid what it was | Array::Agnostic's `is-deeply` |
| 12 | a nested `my sub` lost its lexicals once a closure outlived the frame | Terminal::ANSIParser's whole state machine |
| 13 | `.resolve(:completely)` ignored the adverb | IO::Path::ChildSecure sees the Failure it is built on |
| 14 | `%h<k> := $a` bound the VALUE, not the container | Hash::MultiValue's first test |

**Measured after the fixes** (same 36 dists, same harness, 120 s budget):
**two converted — Clipboard and IO::Path::ChildSecure, the 90-downstream lever**
— and ten more moved past the failure recorded above to stop somewhere deeper:
Apache::LogFormat, Array::Agnostic, BitEnum, Cro::WebApp, Data::Reshapers,
Hash::MultiValue, Stats, Terminal::ANSIParser, Testo and Text::CSV. Roast held:
666 files against the pre-change binary's 669, and all three of the difference
pass STANDALONE on both binaries (harness timeouts under three workers, the
pattern the plan's own notes describe). `t/run.raku` is 955 of 956, and the one
failure — `empty-import-list-imports-nothing.raku`, which needs a P5index this
machine has never installed — fails identically on the pre-change binary.
What the next layer looks like:

- **Text::CSV** — `$csv.CSV(in => …, out => Supply)` answers a Bool where a
  Supply is due (`.tap` on Bool). Data::Reshapers waits behind it.
- **Testo** — `Cannot invoke non-Callable value of type Pair` from `&!group()`,
  through `multi method group(Pair (Str:D :key($desc), :value(&group)))`; the
  destructuring binds standalone, so it is the role/private-method path.
- **Identity::Utils** — `CompUnit::Repository::FileSystem.resolve($spec)` answers
  an IO::Path where Rakudo answers a CompUnit.
- **Stats** — `Cannot resolve caller mode()`.
- **BitEnum** — a role's VALUE parameter (`role R[::T, Str :$prefix]`) is visible
  in the role's methods and attribute defaults but NOT in a `sub` declared in the
  role body.
- **AttrX::Mooish** — its `Attribute` subclass needs the metamodel to answer for
  a user class deriving a built-in.
