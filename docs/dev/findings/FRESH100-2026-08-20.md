# The 100 newest distributions, under `rakupp test`

The first run of the freshness sweep from
[plans/FRESHNESS-PLAN.md](../plans/FRESHNESS-PLAN.md): the 100 most recently
released distributions in the REA index (2026-07-11 … 2026-08-20, ~5½ weeks of
the ecosystem, one entry per dist at its latest version), each put through
`rakupp test` — build hook, dependency install, then its own suite.

Nothing in the engine was changed for this run. It is a measurement.

## Method

- Index: REA `META.json` of 2026-08-20, 14,943 dist-versions / 2,523 dists.
  The 100 newest by `release-date`, latest version of each dist
  ([fresh100/fresh100.tsv](fresh100/fresh100.tsv)).
- Engine: `build-arm64` copied aside as `rakupp-fresh100` before the run —
  **v3.14.0-159-g0039c70** — so a rebuild in another working session could not
  change the engine mid-sweep.
- Store: a private CURI prefix in a scratch directory. The user's `~/.raku` is
  not touched, and nothing from a previous campaign satisfies a dependency here.
- Environment: **`OPENSSL_PREFIX=/opt/homebrew/opt/openssl@3`**. This machine
  has two Homebrews; without it OpenSSL's build hook asks the `brew` on PATH
  (the Intel one) and hands the arm64 binary x86_64 libraries. The first pass
  ran without it and recorded OpenSSL plus the ten dists above it as failures —
  every one of those rows was an artifact of the environment. Set it before any
  future sweep on this machine.
- Budget: 180 s per dist (600 s for the OpenSSL group's re-run). Each child runs
  with stdin closed under `perl -e alarm`, since macOS ships no `timeout(1)`.
- Verdict per dist: `pass` = its own suite green; `self-fail` = its own suite
  fails; `dep-fail` / `dep-build-fail` = a dependency failed first, so the
  dist's own tests never ran; `build-fail` = its `Build.rakumod` failed;
  `timeout` = the budget ran out, in every case inside a *dependency's* suite.
- **No Rakudo control was run except for the parse cluster** (below), so for
  most rows "ours or upstream's" is undetermined. That is the next step, not a
  conclusion of this one.

Raw data: [fresh100/results.tsv](fresh100/results.tsv). Harness:
[`tools/eco-fresh/`](../../../tools/eco-fresh/) — `pick-fresh.raku` (index →
list), `sweep-fresh.raku` (list → verdicts, resumable), `summarize-fresh.raku`
(verdicts + logs → these tables).

## Proven ours: the parse cluster

The one control that is cheap to run without a dependency tree is compilation.
Every module file of the dists that failed to parse was run through
`raku -c -Ilib` and `rakupp -c -Ilib`. Six files across five dists compile
under Rakudo and do not compile under rakupp — no judgement call, no
upstream-brokenness to argue about:

| dist | file:line | rakupp says | the construct |
|---|---|---|---|
| CompUnit::Util | `lib/CompUnit/Util.rakumod:151` | expected variable in declaration (got `*`) | `my ($key, *@path) = $path.split('::')` — a slurpy in a declaration's signature list |
| FINALIZER | `lib/FINALIZER.rakumod:92` | expected `)` (got `:`) | `method finalize(\SELF:)` — a sigilless capture as the invocant |
| Rakudo-Type-Introspection | `lib/Rakudo-Type-Introspection.rakumod:112` | expected `{` (got `str`) | `if try $type.^name -> str $name {` — a native-typed pointy parameter on a statement condition |
| Testo | `lib/Testo.rakumod:170` | expected `{` (got `;`) | `$_ .= Str when Str for $a, $b, $c;` — stacked statement modifiers (`when` then `for`) |
| Gnome::N | `TopLevelClassSupport.rakumod:904`, `GnomeRoutineCaller.rakumod:662` | expected `}` (got `''`) | reported at EOF, so something earlier swallowed the file — needs `tools/blame-parse.raku` |

Four of the five are one construct each. The Gnome::N pair is the campaign's
familiar shape: an error at end of file means a mis-scan ate the rest of it,
and the line it names is not the line at fault.

## The rest, by what it would take

Not verified against Rakudo, so read these as leads, not verdicts:

- **`Kernel.hostname` is missing** — two dists (Sys::Hostname, Email::MessageID)
  die on `$*KERNEL.hostname`. A builtin gap, not a semantics question.
- **`Class 'DateTime' cannot inherit from / compose itself`** (DateTime::strftime)
  is the self-referencing-class bug already on the books from the roast S02
  `perl.t` and the PWC round-one ledger.
- **`Type Array does not support associative indexing`** (Email::Simple) —
  an indexing path that should be an ordinary positional read.
- **`Undefined routine 'with'`** (Compress::LZString) and **`'void'`**
  (Gnome::N) look like a control-flow/type keyword being taken for a call —
  worth a look before assuming they are two separate gaps.
- **The nqp / meta surface**: `nqp::getcomp` (CodeUnit), `.refine_slang`
  (overload::constant), `Method.set_name` (JSON::RepositoryEvent),
  `Raku.legacy` (`if`). Introspection-deep, each small.
- **Environment, not engine**: YAMLScript, YAMLStar, Termbox2, Geo::Valhalla
  and Notcurses::Native fail because a system library or symbol is not on this
  machine. Not ours, not chased. (OpenSSL *looked* like this one and was not —
  see the environment note in Method.)
- **`Qwiratry::*` (4 dists)** fail on their own sibling modules not being
  found — a distribution-resolution question (one dist providing several
  modules), which may be ours or may be how they are published.

## What the sweep found about our own installer

The blocker board is now headed by our own tooling, not by a module:

1. **The install plan ignores what the target store already holds.** Digest was
   installed into the sweep's store with `--no-test`, and the very next dist
   still planned it, fetched it and ran its suite again. Every dist in the
   LLM/MCP/ComfyUI family therefore re-ran Digest's suite — the known ~430 s
   one — before reaching a line of its own tests.
2. **`rakupp test X` tests X's dependencies too.** That is defensible (a
   dependency is installed the normal way, and the normal way runs its suite),
   but combined with (1) it means the measurement of a dist is dominated by
   other dists' suites, and one slow dependency mass-produces timeouts.

Raising the budget does not help: the two dists retried at 900 s were still
inside Digest's suite when that ran out, with 34 further dependencies queued
behind it. **The ten `timeout` rows are blocked by our installer, not by their
own code** — they are the cheapest ten dists in this corpus to convert, and the
conversion is a change to `tools/install.raku`, not to the engine.

## Timeouts

Twelve dists hit the budget without reaching their own suite: ten inside
Digest's suite, two inside Method::Protected's (which fails on its own account
anyway, so those two are a real dependency failure). The verdict table counts
them as `timeout` rather than folding them into `dep-fail`, because what they
say about *those dists* is nothing at all.
