### New

- **`rakupp --doc-links prog.raku`: every construct of a program, linked to
  the page on docs.raku.org that documents it** (a516dd92, b4bf1dc9).
  Keywords, routines and methods, operators, types (native types too: `int`
  to its own page, `int64` or `size_t` to its table on the native-types
  page), special variables, quoting forms and regex constructs, as a list grouped by kind with the lines that use
  each; `--html` writes the program as one self-contained page with every
  construct a link, `--ansi` prints it in the terminal with clickable OSC 8
  links, `--json` gives each link's span and URL. `rakupp doc prog.raku` is
  the same list. Nothing runs and nothing is fetched (50 ms for the
  3,111-line tools/install.raku). The parser decides what a word cannot: a
  prefix from an infix `-`, an item from a list `=`, the program's own class
  from a built-in. A method links to its invocant's type when that is known
  without running the program — a literal, a declared type, a sigil, `T.new`,
  a chain with fixed result types (`$text.lc.comb(…).Bag` is a Bag) — and to
  the type up the chain that documents it (`.total` on a Bag is Baggy's);
  otherwise to the page listing every type's version, with the types named.
  The links come from a committed copy of the docs site's own search index
  (src/raku_docs_index_gen.cpp, 5,251 entries of 2026-11-07, regenerated by
  tools/gen-raku-docs-index.raku), because anchors cannot be derived from
  names; 383 anchors on 131 live pages were checked and all exist. The
  playground's output pane has a **Docs** tab on the same code
  (`rakupp_doc_links()` in Raku.js): the editor underlines what has a page,
  the construct under the cursor is named with its link, Cmd/Ctrl-click
  opens it, and `&docs=1` in a link opens the tab. The playground was
  exercised against the native binary; the wasm build was not run.
  t/regression/doc-links.raku pins 33 constructs to their label and URL and
  holds every link over examples/ to its source bytes.

### Faster

- **Less memory: a `Value` is 64 bytes, not 80** (02e52fa2; VALUE32-PLAN
  design C). A Str of up to 15 bytes now lives in the value's own 16-byte
  string slot, and a longer one is a pointer to a shared body. The slot held a
  32-byte `std::string` and a pointer before. Peak memory, measured against
  the commit before:
  - a million Ints built by `.map`: 164 → 134 MB;
  - a million short Strs: 164 → 134 MB;
  - a million Rats: 242 → 164 MB;
  - 200,000 two-element arrays: 82 → 72 MB;
  - `hashfill`: 52 → 45 MB.

  perf-guard is level (geomean −0.49% over 27 kernels; instructions −0.04%).
  Roast's allocations are within run-to-run noise. A string of 16 to 22 bytes
  now costs an allocation where it cost none: `textsplit`, which keeps 20,000
  of them, uses 26.3 MB where it used 23.6, and runs 9% faster.
  t/run.raku 1,992 of 1,992; Roast 1,425 of 1,425; Roast under ASan finds
  nothing new.
- **A string literal is built once** (5d52a248). Its value is made on the
  literal's first evaluation and copied after that, so a literal over 15 bytes
  no longer allocates each time it runs. Evaluating a 36-byte literal 200,000
  times takes 200,000 fewer mallocs and 12–19% fewer instructions in the
  interpreter. Loops the integer kernels compile are unchanged: their string
  lane still makes a new value per element stored. perf-guard is level, and
  `prepend` gets back the 2% of instructions the 64-byte `Value` cost it.
  `t/regression/str-literal-shared-value.raku` checks that a write through a
  copy never reaches the literal.
- **A long string stored many times is stored once** (f0376fa6).
  - The integer kernels used to build a new string for every element they
    stored. Now they share the one they read, from a variable, an element or
    a literal.
  - A double-quoted `"…"` with nothing interpolated is now the cached literal
    as well; until this change only `'…'` was.
  - Pushing a 36-byte literal 200,000 times takes 4,536 mallocs where it took
    404,533, 5.9 ms where it took 15.3, and 23 MB of memory where it took 48.
  - `"…" xx 200_000` takes 6.3 ms where it took 27.8.
  - perf-guard −1.32% (`prepend` −19.7%, `sharedappend` −19.0%).
- **`%h.elems` is the hash's size** (9b294b72). `.elems`, `.end` and `.Numeric`
  of a hash built a Pair for every entry to count them, one allocation each,
  on every call. `say %h.elems` of a 200,000-key hash makes 4,595 mallocs
  where it made 204,626. A Map, Set, Bag or Mix, a role mixed in, a subclass
  and an augmented `Hash.elems` answer as before.
  `t/regression/hash-elems-size.raku`.
- **An untyped Array of Nums keeps them as doubles** (a3246b12;
  docs/dev/experiments/SELFPACK-EXPERIMENT.md). JavaScriptCore keeps a JS
  array of doubles that way, and checks the kind once in compiled code
  (docs/dev/findings/JSC-VALUES-2026-11-07.md). Here:
  - `my @a = LIST` of 8 or more plain Nums stores their bits, in the packed
    body a `my num @a` has, and `my @v = @u` copies them.
  - The interpreter's loop kernels and `--exe -O`'s unboxed loop lanes read
    and store those words. Each array is checked once on entry, and a bail
    puts back the words a loop stored.
  - Storing anything that is not a plain Num, a bind, an `is rw` element and
    every path that knows nothing of words unpack the array into the Array it
    would have been.
  - `RAKUPP_NO_SELFPACK=1` turns it off.

  ns per operation for the perf review's untyped kernels, off → on:

  | kernel | interpreted | `--exe -O` |
  |---|--:|--:|
  | dot | 100 → 4.9 | 25.7 → 0.48 |
  | matmul | 216 → 9.3 | 34.8 → 1.10 |
  | stencil | 272 → 7.1 | 39.2 → 2.56 |

  Bun's top tier runs the same three at 0.69, 0.81 and 0.79 ns.
  - Peak memory is not lower: the words are built beside the Values.
  - The tree-walker alone, where no kernel takes the loop, runs matmul 16%
    slower.
  - `src/Codegen.cpp`'s ceiling is 10,620 lines, up from 10,500, for the
    lane code.

  t/run.raku passes 1,997 of 1,997, and 1,997 of 1,997 with
  `RAKUPP_SELFPACK_MIN=1`, which packs every Num array. `t/exe/fuzz.raku`
  passes 326 of 326, 70 of them new array programs held to the interpreter with
  packing off. `t/regression/selfpack-arrays.raku` agrees with Rakudo.
- **A loop in a top-level block knows the top level's types** (59764c5a).
  Under `--exe -O`, a loop in a bare block, or in a `do` or `try` block, at
  the top level now types the program's top-level variables as a loop at the
  top level does. `my $a = 3e0` is a Num there, so `$a / $b` is a float
  division and the loop takes the unboxed lane.
  - Before, a bare block refused the lane or kept an Int lane whose guard
    never held.
  - A `do`/`try` block lost its lane when it became a scope of its own
    (37935a34): `t/exe/fuzz.raku`'s 20 `div0` programs, whose loops sit in
    `(try { … })`, have it back (207 lanes of 326, from 187).
  - A block's own `my` of the name still shadows it, in that block and the
    blocks inside it.

  `t/regression/exe-lane-top-types-in-blocks.raku`.
- **A loop that stores into a big packed array no longer logs every store**
  (b9e35683). A loop kernel or `-O` lane that bails puts back the array
  elements it stored, so it logs what each store overwrote. The log used to
  switch to a copy of the arrays only once it held more entries than they hold
  words. Now it switches at a sixteenth, since copying a word costs a fraction
  of logging one.
  - FORTRAN-LESSONS' axpy, `c[i] = 2*a[i] + b[i]` over ten million doubles:
    26.4 → 13.8 ms compiled and 82.3 → 71.4 ms interpreted. gfortran takes
    2.55 ms.
  - A loop that stores a few elements still only logs.
  - docs/dev/findings/FORTRAN-PACKING-2026-11-07.md has the kernels against
    gfortran 16.2.

### Fixed: silent wrong answers

- **`return-rw` wrote into, or read from, the frame it had just left**
  (7a09c596). When a routine returns, its frame goes back to a pool and its
  variables are cleared. Two paths used one of those variables afterwards.
  - Assigning through an `is rw` call wrote the value into the returning
  routine's own copy of a sigilless parameter.
  `sub raw-id(\c) is rw { return-rw c }; sub set(\c, $v) { raw-id(c) = $v; c }`
  does that.
  - A `return-rw` of the routine's own local was read back only after the
  frame had been cleared.

  On most systems the freed memory still held the old bytes, so nothing
  showed. musl's allocator reuses it sooner:
  `t/regression/rw-sub-lvalue.raku` crashed with SIGSEGV on linux-aarch64-musl
  in CI. Both bugs are older than this release's other changes, and ASan
  found them only once it could see the engine's own pools free memory
  (f3096c7d: an ASan build now hands every slab and list block back to the
  allocator).
- **Right after `await start {…}`, a worker still exiting counted as running
  code** (578572c6). For as long as its thread took to tear down:
  - `my $b := $a` would not share `$a`'s cell, and `$b.VAR.default` died;
  - a callee did not see a `my $*X` declared later in its caller's frame.

  Both depended on timing, which is why CI's Linux legs failed
  `scalar-alias-keeps-type.raku` or `dynamic-var-memo.raku` now and then.
  The checks that ask whether another thread can be running code now count
  worker bodies, which end when the body returns.
  `t/regression/worker-teardown-is-not-a-running-body.raku` makes the
  teardown slow on purpose (`RAKUPP_WORKER_EXIT_DELAY`).
- **Under `--exe`, a `do { … }` or `try { … }` block in an expression was not
  a scope of its own** (37935a34), as a bare block is. Two things came of it:
  - At the top level, a `my` inside one that shared a top-level variable's
    name assigned that variable. `my $j = 7; my $r = do { my $j = 100; $j }`
    left `$j` at 100 compiled, and at 7 interpreted.
  - A C-style `loop (my $a = 0; …)` inside one did not build, with or without
    `-O`: the generated C++ assigned `v_sa` and never declared it.

  A top-level `do` block that declares a dynamic (`my $*x`) now runs bundled
  with the interpreter, as a bare block there already did. Compiled natively,
  it died with `Undefined routine` when the block also declared the sub that
  read the dynamic. `t/regression/exe-do-try-block-scope.raku`.
- **A `for` loop over an array that another thread was pushing to could crash**
  (9b7a9824). Before looping, `for` checks the list for a literal `IterationEnd`.
  It read the array without the lock `push` takes, so a push that moved the
  buffer left the check reading freed memory. The values a loop sees while
  another thread grows its array are still unspecified, but the runtime no
  longer crashes. It crashed now and then on linux-aarch64-musl in
  `t/stress/ub-iterate-during-push.raku`, and an ASan build with the pools off
  reported it in 1 of 12 runs; it now runs 40 of 40 clean.

- **A `constant` naming a type is that type in a signature** (28257097;
  issue #220). `my constant Alias = Foo::Bar; sub g(Alias $x) { }` gave a
  parameter whose `.type` was a type named Alias, `=== Foo::Bar` False,
  and a signature rendered `:(Alias $x)`; Rakudo resolves the constant at
  compile time and answers Foo::Bar. The binder and the return check
  already resolved the name per call; `.type`, the parameter's and the
  signature's rendering, `--> Alias`, `.returns` and `.signature.returns`
  now resolve it in the routine's closure too, so a role's method in `class
  RI does R[Int]` has an `Int $x`. Found beside it, the binder dropped a
  parameterization: `constant AI = Array[Int]; sub f(AI $x)` took an untyped
  Array, and `multi m(AI $x)` won over `multi m(@x)` for one; both refuse
  it now, as Rakudo does. t/regression/constant-type-alias-in-signature.raku
  agrees with Rakudo 2026.09, interpreted, under `--jit`, `--cnp` and
  `--exe`.

- **`Array.WHICH` and `List.WHICH` are identity, as `===` is** (266d37c6,
  92561fe1; issue #221). They were the type and the elements joined by a space:
  `@a.push(3)` moved `@a.WHICH`, two arrays holding 1, 2 had one WHICH and
  were one element of a Set or a Bag, and `[1,2]`, `["1","2"]` and
  `["1 2"]` were all `Array|1 2`. An Array, a List or a Seq now identifies by
  its payload, which every copy shares and a push or a refill leaves in
  place; a typed one is `Array[Int]|…`, `Empty` is still one object, and a
  Capture and a Junction are still values. An identity is a serial now, not
  an address, which the next body took once a temporary was gone: `(1,2).WHICH
  eq ('1','2').WHICH` was True, as were two temporary objects, Hashes, Bufs
  and Instants. A Set of 200,000 objects takes 0.058 s where it took 0.050,
  and each live body asked for its WHICH holds about 42 bytes more. Found beside it, `(elem)`
  flattened the list it searched: `@b (elem) (@b.item,)` was False and
  `2 ∈ (1, (2, 3))` True. `t/regression/issue-221-array-list-which-identity.raku`.
- **`Positional[Int] ~~ Positional[Mu]` is True** (28824bb7; issue #222).
  Two type objects of a built-in parameterized role matched only with
  identical arguments, which is right for a class (`Array[Int] !~~
  Array[Numeric]`) and wrong for a role: Rakudo asks each argument on the
  right to accept the one on the left. A `:D` argument on the right takes
  only itself, since the left one is a type object; a nested
  parameterization asks again a level down. PDF::COS::Tie's
  `$att.type !~~ Positional[Mu]` warned four times on `use PDF::Content`.
  `t/regression/issue-222-parameterized-role-arguments-smartmatch.raku`, 52
  rows against Rakudo 2026.09.
- **A `--> Int:D` after a parameter is checked** (32b1ea01). Only a `-->`
  that opened the signature kept its smiley, so `sub j($p --> Int:D) { Int }`
  returned the type object Rakudo refuses, and the signature read
  `($p --> Int)`. `t/regression/signature-text-names-types-as-raku.raku`.
- **A sub beside a routine its scope imports is a redeclaration**
  (eb574770; issue #230). `unit module Mine; use Other; sub run-word {…}`,
  where Other exports a `run-word`, compiled and kept the local sub; Rakudo
  refuses it with "Redeclaration of symbol '&run-word'.", and in the
  reporter's 2,000-line module calls reached the imported one, so the output
  changed with nothing said. Every import road stepped aside for the local
  name, and a `sub EXPORT`'s map was bound over it. Now it is
  X::Redeclaration in either order: for `sub`, `my sub` and `our sub`; in a
  module, the mainline, a block, a routine body, or a class or package body;
  after `import`; for a `sub EXPORT`; and in `--aot` and `--exe` binaries.
  The error names the `use`'s file and line. A multi beside an imported sub,
  or a proto beside an imported group, is `Redeclaration of routine 'f'.
  Did you mean to declare a multi-sub?`, as on Rakudo. Two multis still
  merge, a local sub still completes an imported stub, and a selective export
  the `use` did not ask for, `need`, `use M ()` and a `use` in another scope
  still clash with nothing. It is raised when the `use` runs, so there is no
  `===SORRY!===` header, and a `use` in a routine body reports it at the
  routine's first call. `t/regression/import-over-local-routine.raku`, 38
  checks against Rakudo 2026.09.

### Fixed: crashes

### Behaves like Rakudo

- **Two PDF::Content declarations compile** (1a3f36d1; issues #223 and
  #224), so `use PDF::Content`, and PDF::Lite above it, gets past them. A
  named sub nested in a method takes a `$!attr` parameter
  (`sub STORE($, $!text) { … }`, handed to a Proxy), binding into the
  method's `self` as an anonymous `sub ($!x)` there does; a sub at the top
  level or in a class body is still refused. `my subset S of ::?ROLE:D is
  export(:S) where { … }` reads the enclosing type, where the `::?ROLE:D`
  became a statement of its own and `is export(…)` a call to a routine
  named `export`. `t/regression/issue-223-224-pdf-content-declarations.raku`.
- **A class's FALLBACK answers `.name` again** (e7bbb97c; issue #225, a
  regression since 5.0.0). The built-in arm that makes `42.name`
  X::Method::NotFound threw before the unknown-name path, where FALLBACK has
  run since 0cc5b2bd moved it there; on a user class the arm now hands the
  name on to `handles *`, FALLBACK and `.^add_fallback`.
  `t/regression/issue-225-fallback-gets-name.raku`.
- **A signature names NativeCall's types as their `.raku` does** (32b1ea01;
  issue #220's follow-up): `sub f(Pointer $x)` is
  `:(NativeCall::Types::Pointer $x)`, as on Rakudo, while the type itself
  is unchanged. A coercion renders its target's smiley first,
  `Str:D(Int) $y` (it was `Str(Int):D`), and `--> Str()` as `--> Str(Any)`.
- **A program ends at once past a worker blocked in a read** (17d28f81;
  issue #229). `exit`, or the mainline's end, while a `start` waited on
  `$*IN.read`, `.get`, `.slurp` or an `is native` read(2) that nothing would
  satisfy took 2.2 s: drainWorkers waited out its whole 2 s grace for a
  worker that could not see the shutdown flag, then abandoned it anyway. A
  worker parked in such a call is now counted, and the drain stops waiting
  once every live worker is one: 0.25 s, where Rakudo 2026.09 takes
  0.32-0.44 s. `t/regression/issue-229-exit-past-blocked-read.raku`.

### Platforms and packaging

- **`raku++` is a command of its own in every distribution** (e1245a6c).
  The product is Raku++; the command was only `rakupp`. `cmake --install`
  now puts `bin/raku++`, a relative link to `rakupp`, beside the binary, so
  every POSIX archive, the `.deb` (`/usr/bin/raku++`), the Docker image,
  Nix, Guix and a source install have it, and `raku++ --exe` compiles as
  `rakupp --exe` does. Nothing else claims the name, so unlike `raku` it is
  not a question. The Windows zips carry no second `.exe` (a zip stores no
  links, and the copy would be about 7 MB more to download):
  `install-windows.ps1` makes `raku++.exe` a hard link and the wizard
  installs a copy. `install.sh`, the Dockerfile and `rakupp upgrade` make
  the link when an older archive has none. Found on the way: `rakupp
  upgrade` run as `raku` on Windows looked in the zip for a `bin\raku.exe`
  it never had, and remade the `raku` name with `cp -p`, which plain Windows
  cannot run; it looks for `rakupp.exe` and uses the engine's own hard link
  and copy now. t/unix/install.sh passes 44/44 here against a tarball
  packed from the build; `rakupp upgrade` was run end to end against local
  archives. The PowerShell scripts, the wizard, the `.deb` and the image
  were not run here; CI's legs run each. The Homebrew tap's prebuilt
  formula installs `bin/rakupp` alone and is unchanged.

### Tools

- **`rakupp install` cleans up without `rm`** (20f0691d; issue #228). Its
  three scratch directories were removed with `rm -rf`, so on Windows every
  distribution printed "'rm' is not recognized" and the last cleanup died
  in an END with X::Proc::Unsuccessful, though the installs succeeded. They
  are removed in Raku now: a symlink unlinked and never followed, a
  read-only file made writable first. Found beside it, the directory an
  install from a URL unpacks into was never removed, on any platform; it
  goes at the end too. Not run on Windows.

### Left open

- Found with eb574770, the same before it (each in TODO-FOLLOW-UPS.md): a
  `my &f`, a `my $v` or a class beside an import of its name compiles, where
  Rakudo refuses it; two imports of one name in a block keep the first,
  where Rakudo keeps the last (the mainline keeps the last); and `use Test;
  sub ok(…)` compiles, because Test's routines are built in rather than
  imported.

- Found with 28257097, the same before it: an attribute typed by a
  parameterized alias, `constant AI = Array[Int]; has AI $.a`, takes an
  untyped Array (the attribute resolver keeps the bare name, which
  NativeCall's `Pointer[void]` aliases lean on), and `my AI $z` answers
  `.VAR.of` AI where Rakudo says Array[Int]. `multi n(Array[Int] $x)`
  written out never takes a typed array, where Rakudo's does. A role
  method's signature leaves out its invocant (`:(Int $x, *%_)` against
  Rakudo's `:(RI $:: Int $x, *%_)`), and `&c:(Foo)` renders as `&c`.
- Found with issues #221-#229, the same before them (each in
  TODO-FOLLOW-UPS.md): a value-parameterized role, `R2[1] ~~ R2[Int]`, is
  False where Rakudo says True; `Positional[Int:D].^name` is
  `Positional[Int,D]`; `%h{@b.item} = 1` assigns a two-key slice; a FALLBACK
  receives the list methods Any answers (`.first`, `.elems` …), and an
  object that is no Exception keeps `.throw`, `.rethrow`, `.resume` and
  `.backtrace` from its FALLBACK; a `my subset` in a `unit role`'s file is
  not named for its package.
